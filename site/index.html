    System One models read a situation and answer typed questions in one fast call: yes or no, pick one option, or score a level, each with probabilities. Every model gets the same cases and the same request body, scored against each dataset's labels. Text and images are scored as two separate tracks.

    System One Bench is a living benchmark: we keep adding models as they're released, and every new model runs the same cases. See the roadmap for what's next.

    Calibration error is the average gap between a model's stated confidence and how often it's right, in percentage points. A well-calibrated model's 80% answers are right about 80% of the time.

      Method

      What's measured

      • Each case is a state plus one to five named questions, sent unchanged to every model.
      • Accuracy compares the most likely answer with the dataset's label. A failed call counts as wrong.
      • Text and images are two tracks with two indexes: the System One Index over 16 text datasets, and the Vision Index over 5 image datasets. They rank models separately, so a model can lead one and not the other.
      • Calibration error is top-label ECE over 10 bins. Log loss, Brier score and more are in results.json.
      • Cost is the summed usage.cost the API reports.
      • Latency depends on the network between caller and API, so every API model was timed again on 15 October from one cloud server, all 3,250 cases through OpenRouter with 8 requests in flight. Only latency comes from that run; accuracy, calibration and cost come from each model's original run. The models added on 25 October were timed in their own runs from a similar cloud server, also 8 in flight; Jev 1.14, run again alongside them as a control, measured 122 ms there against 136 ms on 15 October. The models added on 30 October ran from a machine where the same Jev 1.14 control took 492 ms, so they have no latency on the board. GLiDE, added on 2 November, ran on Fastino's own API from that machine, where the control took 521 ms, so it has none either; nor do Celeris-1 Decision and meraGPT's Decider 1, added on 8 November from another machine on their own APIs, or Gemini Decision 1, added on 11 November on Google's own API. Open-weight models ran locally, one call at a time: Laya on an Apple M5 GPU, the open-weight d1, d3, Kev and Naluri sizes on a 4-vCPU cloud CPU, and Dexy-Decision-9B, added on 11 November, on a cloud A100 GPU. Their timings aren't comparable with API round trips, so they stay out of the latency charts.
      • The vision track ran on 15 October from a cloud server, 8 requests in flight per model, and on 25 October, 30 October, 2 November and 11 November for the models added then (the last three from different machines, which doesn't change accuracy). It sends each image once, as a base64 PNG or JPEG in state, resized to fit every model's limits. Box answers count as right when they overlap the labelled box by at least half (IoU of 0.5 or more).
      • The data is frozen: data.lock.json holds a SHA-256 for every dataset and image, every source is pinned to a fixed version, and runs are refused on data that doesn't match.
      • Nothing was tuned on test data. A model marked in-domain trained on another split of some of the datasets tested here, as its maker disclosed: open a row to see which datasets, and its index without them, ranked against every model on those same datasets. Its index still counts all 16, like every other model's. Models whose training data isn't published may overlap too; we can't tell.
      • A score marked unusually high is far above what that model's other datasets, and every other model's score on that dataset, predict: at least 10 points, and 3.5 times the usual spread once sampling noise is counted. It often means the model trained on that dataset or one like it, disclosed or not. It isn't proof, no flag isn't proof of the opposite, and the score still counts. The benchmark pages give the numbers.

      Run it yourself

      export OPENROUTER_API_KEY=<your key>
python run_decisions.py --model openai/gpt-6-luna-decisions --name luna
python run_decisions.py --model typesafe/jev-1.13 --name or_jev
python score.py preds_or_jev.jsonl preds_luna.jsonl

      To race two models live on the same cases, run python server.py and open localhost:8061. The race needs API keys, so it runs on your machine rather than on this page.
